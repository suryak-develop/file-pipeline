## How It Works — Step by Step

1. **File Upload** — User or application uploads any file (PDF, image, JSON, CSV) to S3 bucket with versioning enabled
2. **S3 Event Trigger** — S3 automatically fires an event notification to Lambda #1 on every new upload
3. **Message Queue** — Lambda #1 pushes file details (bucket, key, size) to SQS queue for reliable, decoupled processing
4. **Processing** — Lambda #2 is triggered by SQS, reads the message and processes the file metadata
5. **Storage** — Processed metadata saved to DynamoDB with auto-expiry (TTL = 30 days) for cost efficiency
6. **Notification** — SNS sends a real-time email alert confirming successful processing

## Key Technical Concepts Demonstrated

- **Event-Driven Architecture** — services communicate via events, not direct calls
- **Decoupled Microservices** — each Lambda has a single responsibility
- **Infrastructure as Code (IaC)** — entire stack provisioned via CloudFormation template
- **Least-Privilege Security** — each Lambda has only the permissions it needs
- **Auto-Scaling** — Lambda and DynamoDB scale automatically with load
- **Cost Optimization** — serverless = pay only when code runs, DynamoDB TTL auto-deletes old records
- **CI/CD Automation** — GitHub Actions deploys on every push to main, zero manual steps
